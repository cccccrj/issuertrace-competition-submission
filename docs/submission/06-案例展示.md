## 1 从公告到事件、主张和证据

输入：长鑫科技「关于召开2026年半年度业绩说明会的公告」，来源URL及event_id见 [case-event.json](evidence/isolated/case-event.json)。

处理：正文解析／事件标签 → 区分公告发布日期2026-08-29与拟定会议日2026-09-07 → 抽取主张 → 同一披露段落检索与引用 → 风险排序 → 导出Word。

输出：类型RESPONSE_CLARIFICATION、neutral／minor、risk_score=25、low；主张保留原文连续跨度，SUPPORTED，引用公告第1页。完整数据和 [实际导出DOCX](evidence/isolated/case-event.docx)可交叉核对。

评价：HTTP详情与导出成功、Word ZIP结构有效、证据与页面可定位，实现从公告到结构化事件、主张核验和报告导出的完整链路。案例指标评价本例流程，整体算法质量按独立评测集统计。

## 2 风险助手：区分证据状态并提供来源追溯

输入：药明康德风险事项 `9cba9d7127b83a1b6492b6ec`，问题「这条风险有哪些事实依据？请区分机器判断与待核验内容。」

处理：读取风险档案 → 查看主张核验 → 查来源事件 → 组织带来源的回答。实时步骤与完整响应见 [assistant.json](evidence/production/assistant.json)。

实际输出：available=true，6句回答，dropped=0，incomplete=false；分别解释机器风险分与可信度，将核心主张的UNVERIFIABLE核验状态清晰呈现，为补证和业务复核提供指引。首次SSE事件0.136秒，总计42.046秒，按单次公网案例记录。

评价：引用标识均绑定本次返回的sources，具体对象可通过label/link定位；模型解释与人工复核分层展示。助手实现风险档案、核验状态与原始来源的关联查阅，支持复核人员逐句对照证据并确认业务结论。

## 3 人工协同全流程（隔离数据库）

输入：同一风险档案，由analyst和reviewer两个角色依次操作。

```text
pending → investigating（分析师认领、保留机器结论）
        → reporting（提出结论、交指定复核负责人）
        → returned（复核负责人说明理由；恢复原上报分析师）
        → reporting（分析师补证后再次上报）
        → archived（复核归档）
```

输出与约束：viewer写入403；缺结论上报422；上报后analyst改判403；无理由退回422；归档再开启409。个人通知仅包含公开通知或本人收件，账号管理对analyst403。见 [65项验收](evidence/isolated/acceptance.json)。

另一个事项的10路同时保存全部返回200，新增10条带不同意见的审计历史，实现并发意见完整留痕。同状态多次保存采用最后一次写入生效，适用于本次单实例协同；排他认领、乐观锁与多节点事务可按扩展协议验证。
