# 模型、算法与参数说明

本系统采用预训练模型直接推理，通过提示词、规则校验和检索编排适配金融事件任务，并结合独立离线向量计算。算法参数以源文件及随库保存的model_name／prompt_version为准，问答模型配置和历史批处理结论分别管理。

## 1 方法与实现入口

| 方法 | 实现 | 参数／边界 |
|---|---|---|
| 事件抽取 | processor/ai_label.py | event-label-v8；temperature=0；文本片段上限12000字符；默认workers=1，可选1～8；结构契约校验 |
| 数值归一与校验 | processor/normalize.py、claim_verdict.py | Decimal处理单位倍率、币种和百分比；规则验证数值条件，披露证据与主张核验共同评价语义支持关系 |
| 证据检索 | processor/claim_index.py | SQLite FTS5 BM25；中文二元组、繁简折叠；最多20稀有查询词，常见词占比阈值0.08；段落最低20字符 |
| 主张核验 | processor/claim_verdict.py | claim-verdict-v3；候选5条，每条最多600字符；每25条小批量提交；四值结果与PARTIAL子类 |
| 向量召回 | scripts/gpu/embed_neighbors.py | BGE-M3，L2归一余弦；同公司内top-k20；GPU上FP16；冻结batch64、max_length512；4090D全量复测见08 |
| 混合／兜底 | processor/dense_index.py | RRF_K=60、FUSION_DEPTH=20；fallback最多追加2条dense-only候选；索引指纹防错配 |
| 研判助手 | api/assistant.py | 6种只读工具；最多6步；问题300字符；观察2400字符；引用摘录160字符；单次网关45秒 |
| 近重复聚类 | [pipeline.py：build_duplicate_clusters](../../processor/pipeline.py) | 同公司候选；SimHash 8 bands、Hamming≤16；同标题Jaccard≥0.72、纯正文≥0.86；同标题containment≥0.80且日期差≤7天；模板数字否决默认关闭（TEMPLATE_TEXT_BAR=None） |
| 版本比对 | [disclosure_diff.py：align_sections／diff_section](../../processor/disclosure_diff.py) | 相邻版本正文／章节→数字、增加、删除、修改记录；REWRITE_SIMILARITY=0.60、段落最低30字符；METRIC_WINDOW=24、MIN_METRIC_CHARS=2、MAX_FIGURE_DIGITS=15；默认prospectus、仅有页码版本 |
| 传播关联 | [propagation.py：duplicate_edges／sequence_edges](../../processor/propagation.py) | 重复簇、裁决及同事项时序→有来源的传播边；REPOST=0.90、FOLLOW_UP=0.30、REACTION=0.15；回看30天／最多40候选 |
| 问询与披露关联 | [inquiry_align.py：align_question](../../processor/inquiry_align.py) | 问询结构、答复段落及披露差异→关联三元组；稀有共享词门槛12、短问题分母3、分数≥0.05、每问题最多5个差异 |
| 事项标签与行业约束 | [issue_codes.py](../../processor/issue_codes.py)、[issue_scope.py：backfill](../../processor/issue_scope.py)、[pipeline.py](../../processor/pipeline.py) | 文本预算1800字符、每事件最多2标签、issue-codes-v2；按公司行业校验标签，生命周期写入事项与状态历史 |
| 候选因果 | [causal_link.py：merge_candidates](../../processor/causal_link.py) | 五条候选路径→带方向与证据的候选关系；共享要素≥2、通用要素cutoff=60、时间窗90天；显式引用回看30天、containment≥0.60；causal-link-v1、单侧文本1200字符、主张最多5条 |
| 查询 | api/routes/、api/db.py | 参数化SQLite查询、固定字段与分页；助手不生成任意SQL，不执行模型自由输出SQL |

线上批量结论主要来自qwen-plus；在线助手单独选kimi-k3。模型权重和API密钥独立管理。temperature=0用于降低采样随机性，模型名称、提示词版本与运行结果留存，支持远端服务版本变化时的结果追溯。

上述配置为提交源码默认参数；算法评价设计与样本口径统一见[测试报告](05-测试报告.md#算法质量评价)。关键方法如下：

- 聚类先按公司约束生成SimHash分带候选，再用标题与正文Jaccard判断相似性；同标题包含度分支支持短讯与长文转载匹配。成员与代表文档逐一比较，代表按发布时间选择。参数在train切分标定，test按冻结配置评价；模板数字否决分支保留为默认关闭的可选实验开关。
- 版本比对按相邻披露版本对齐章节和段落，识别正文增删改与数值变化，并保留版本、页码及文本定位。问询关联将问题与披露差异按稀有共享词匹配，输出可供复核的候选三元组。
- 传播分析结合重复簇、同事项时间顺序和来源，形成转载、后续报道与反应边；同一传播分量用于来源独立性计数，边类型与分数按实现配置保存。
- 候选因果结合主张、显式引用、共享要素及时间窗生成候选，再输出带方向和证据的关系供人工研判；其评价按独立因果标注协议开展。
- 事项按标签及公司行业约束归并，维护机器状态历史；人工研判与处置独立留痕，支持机器依据和人工结论共同追溯。

聚类阈值来自对应train标定记录；传播、版本对齐和候选关系的默认阈值属于可配置工程参数，其实现契约与流程由回归测试验证，质量按各自标注集评价。

## 2 检索与裁决

BM25承担平台证据搜索与助手查询；BGE-M3通过离线GPU批处理生成近邻，向主张裁决提供可选fallback／hybrid输入。相似度用于候选排序，事实支持关系由披露证据与四值裁决评价。索引paragraph_fingerprint及输入SHA-256匹配校验确保近邻与当前段落版本关联正确。

裁决输出：SUPPORTED（得到支持）、PARTIAL（部分支持，包括时间／数量／主体／限定词／因果附加等）、CONFLICT（明确矛盾）、UNVERIFIABLE（当前证据不足）。非UNVERIFIABLE结果需要可定位披露依据。人工review_decisions和alert_dispositions是独立记录，不覆盖claim_verdicts。

## 3 来源约束、安全控制与人工复核

系统实现材料与指令隔离、JSON契约校验及工具白名单。助手引用与本次检索结果绑定，过滤缺少来源的句子，提供来源追溯、原文定位与人工复核入口。引用与回答的语义支持关系结合披露内容及业务复核确认，形成检索、解释、复核的闭环。服务状态通过available显式返回，离线模式保持查询、阅读、导出与协同可用。

## 4 实验复现

评测入口为[processor/benchmark.py](../../processor/benchmark.py)，样本和运行记录随处理后评测库交付。事件类型、影响方向、近重复聚类的已测质量及分母见[测试报告](05-测试报告.md#算法质量评价)；证据裁决、数值支持和候选关系采用各自独立人工标注协议。参数与提示词选择使用train，test作为公开验证集报告冻结配置结果；独立盲测按另设数据协议执行。单元测试使用独立合成夹具验证实现契约。

```bash
python -m processor.benchmark --help
```

运行包已带处理后评测数据库，既有结果可直接查询benchmark_runs及benchmark_metrics；重新评价按上述命令帮助选择任务、切分及模型配置，模型路径需配置自有API。

向量导出不需要GPU：

```bash
python -m processor.dense_index export --out artifacts/gpu-bundle
python scripts/gpu/embed_neighbors.py --help
```

GPU环境配置torch、sentence-transformers与授权模型权重，计算产物回传平台导入与评测。正式结果使用真实CUDA与BGE-M3；fake-encoder作为独立联调模式使用。

## 5 GPU已完成实验与扩展协议

### 本次已复现的CPU检索效果

冻结快照上的CPU评价复用已有BGE-M3近邻；4090D全量重算及回传复核见08。启发式检索标签基于同公司内至少两项显著数值共现或英文6词连续片段，排除主张自身源文档。跨语195、数值357、英文原句842三个样本集独立展示，去重联合为1175条主张；此处评价候选命中，独立人工事实评价按另设协议开展。

| 1175条联合样本 | BM25 | Dense | Hybrid | Fallback |
|---|---:|---:|---:|---:|
| recall@5 | 0.8826 | 0.6689 | 0.8757 | 0.8826 |
| 实际候选中命中率 | 0.8826 | 0.6689 | 0.8757 | 0.8936 |

Fallback在BM25五条候选上最多追加两条向量候选，实际候选命中率达到0.8936，BM25基线为0.8826；该配置明确记录五条／最多七条的候选预算。经固定策略评价，提交方案保持BM25主路径和可选向量兜底，以保留英文原句检索表现。Hybrid对照的跨语recall@5增益为0.0052，英文原句recall@5变化为−0.0273；预先设定的全局替换标准为增益≥0.10且损失≤0.02。完整分组、UNVERIFIABLE子集与方案选择见 [retrieval-evaluation.json](evidence/retrieval-evaluation.json)。

### 4090D完整计时与复现协议

本轮在独立4090D服务器对同一输入哈希、93209段落／3922查询、batch64／max_length512／top-k20执行3次完整复测，实际CUDA采样、向量归一、查询覆盖与同公司范围检查均通过。全流程平均58.028秒，编码平均57.360秒，近邻平均0.393秒，驻留显存峰值3493MiB，完整结果见08及evidence/gpu-timing/。权重摘要、实际依赖和基准脚本摘要一并冻结。

三轮完整计算开始前先预热，编码／近邻阶段前后进行CUDA同步，均值、样本标准差、P95、torch峰值及每250ms GPU采样分别记录。导入使用原dense_index.install，在私有新目录完成摘要、段落指纹及3922条主张关联检查，冻结运行近邻和裁决不被替换。FP16分数验收采用0.005舍入容差，原分数和排序保持不变。GPU环境锁与安装要求独立于轻量平台依赖。

历史V10032GB、同规模输入约161.6秒作为已有记录独立保留；历史模型revision、驱动和软件未完整冻结，因此本轮分别报告设备结果，严格跨设备加速比另设同条件对照。双V100的实际多卡并行需有实现和日志。更多GPU硬件、batch、长度及训练实验按07扩展，计算性能与历史算法质量采用各自对应证据。
