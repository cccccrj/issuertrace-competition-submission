# 可运行原型：部署与访问

## 系统体验方式

本地入口：`http://127.0.0.1:8000/`，启动命令见下文。本地多角色演示账号见 [ACCESS.md](../../ACCESS.md)。线上体验地址与评审凭据通过比赛指定渠道单独提供，不随公开材料分发。

本地 reviewer 角色支持检索、阅读、导出与业务复核。多人协同及所有压力写入都在隔离实例的独立数据库完成；远程实例通过 SSH 端口转发连接本地回环地址后测试。

## 本地原生部署（无需GPU）

推荐 Linux x86_64、Python 3.12，完整API及测试套件以支持PEP701表达式的Python3.12环境运行。前端构建用 Node 22.22.2 或更新的22版本、npm。准备约2GB磁盘、建议4GB以上可用内存；实际容量以 Release 清单为准。

1. 克隆本仓库，检出 Release 对应标签。
2. 下载同一标签的部署包及 SHA256SUMS，校验并在仓库根目录解压。
3. 建Python环境、安装依赖，然后启动：

```bash
git clone https://github.com/cccccrj/issuertrace-competition-submission.git
cd issuertrace-competition-submission
git checkout v1.0
gh release download v1.0 --repo cccccrj/issuertrace-competition-submission \
  --pattern 'issuertrace-runtime-v1.0.tar.gz' --pattern SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
tar xzf issuertrace-runtime-v1.0.tar.gz
python3.12 -m venv .venv
.venv/bin/python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements-submission.lock.txt
bash scripts/submission_start.sh
```

访问 http://127.0.0.1:8000，使用 ACCESS.md 的本地账号。运行包已带 web/dist 和两套 SQLite，不需要 Node、GPU或模型网关就能浏览已有事件、风险、证据、关系和评测，并进行独立人工协同。

上述命令对应v1.0资产；运行包内部路径为`data/`、`web/dist/`等相对路径，解压工作目录为对应标签的源码根目录。完整处理后业务库与评测库可直接使用。

若从源码构建前端：

```bash
cd web
npm ci
npm test
npm run build
```

运行包支持无GPU、无模型密钥的离线浏览、查询、导出与协同；配置模型网关后启用智能问答。系统通过available状态清晰区分模型服务就绪情况。采集与模型标注模块可按任务配置来源、网络访问与模型网关。

## 配置

4090D独立批处理部署已完成BGE-M3向量编码与同公司近邻全量复测。GPU部分只需scripts/gpu/、授权模型和受控导出输入；平台仍以Python3.12运行，独立GPU脚本可用已验证Python3.10环境。安装scripts/gpu/requirements-submission.txt后，按08报告复现。权重、原始输入、SSH口令和API密钥独立管理，不进入Git或报告包。

脚本默认单worker、仅监听127.0.0.1。可用 SUBMISSION_PORT、SUBMISSION_HOST、SUBMISSION_PYTHON覆盖。公网部署必须使用HTTPS反向代理，显式配置随机 AUTH_SECRET，设置网络访问控制并轮换比赛密码。环境变量通过当前shell／服务注入；不要假定复制 .env.example 会自动加载配置，也不要提交真实 .env。

可选项：LLM_API_KEY、LLM_BASE_URL、LLM_MODEL、ASSISTANT_MODEL；通知外发通过 NOTIFY_WEBHOOK_ALLOWLIST 和独立secret_ref配置，默认保持dry-run。只设置密钥不会自动重新计算已有裁决。

## 复现测试

```bash
.venv/bin/python -m unittest discover -s tests -v
cd web && npm test && npm run build
```

HTTP脚本读取本地受保护凭证JSON，不能把密码放命令行或日志。重新生成本地账号或清空人工记录前先备份；`submission_prepare.py sanitize`只用于新建的提交副本，禁止对生产目录执行。压力脚本仅针对隔离实例，需要50个独立load账号；默认30分钟50用户阶段，另有4分钟预热分级阶段。

在本地部署的**独立可丢弃副本**运行HTTP验收：

```bash
.venv/bin/python scripts/submission_prepare.py credentials
.venv/bin/python scripts/submission_test.py smoke --base http://127.0.0.1:8000 \
  --accounts .private/accounts.json --out artifacts/acceptance --isolated
```

`credentials`从ACCESS.md导入配套账号，不更改数据库口令。`--isolated`验收会生成测试意见与通知记录，绝不能指向公网生产入口。重新制作快照的sanitize额外要求`--confirm-disposable-copy`，该选项不是生产清库授权。

重放负载需把副本目录命名为`lcei-submission-test-replay`（load账号工具有目录防误操作保护），先执行`submission_prepare.py load-accounts`创建50个独立身份，再执行`submission_test.py load --base http://127.0.0.1:8000 --accounts .private/accounts.json --out artifacts/load --duration 1800`。请先确认该端口确属复制的数据与独立服务，不能复用真实业务库。

## 常见问题

- 登录401：核对账号、环境和停用状态；ACCESS.md仅列本地演示身份，线上评审凭据通过比赛指定渠道单独提供。
- 页面404：确认web/dist/index.html存在，且与源码版本配套。
- 评测页空白：确认benchmark.sqlite3随包解压；分析库不是评测库。
- 启用智能助手：配置模型网关及密钥后启用；离线模式可直接使用已有分析、检索和协同功能。
- 如何查看评测数据：运行包已含处理后的benchmark.sqlite3，直接访问评测页面；单元测试采用独立合成夹具。
- SQLite并发配置：采用单API进程、独立测试数据库及30秒busy_timeout；本次按单实例验证，多节点与扩展负载按专门容量协议评估。
- GPU部署：平台界面和业务查询可直接在CPU环境运行；向量近邻批处理按04／08使用独立GPU服务器。
